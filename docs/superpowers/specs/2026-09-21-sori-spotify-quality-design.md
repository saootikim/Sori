# Sori "Spotify급 퀄리티" 설계

- 작성: 2026-09-21. 사용자가 "질문하지 말고 알아서"라고 위임해서, 결정은 전부 이 문서에 근거와 함께 남긴다.
- 대상: Android Sori (Metrolist 포크, `C:\dev\sori`). Windows는 사용자가 나중에 직접 만들 예정이라 범위 밖이다.

## 1. 목표

"Spotify처럼 느껴지는 앱"을 만든다. 구체적으로:

1. **정체성이 일관된다.** 항상 어두운 중립 회색 바탕에 브랜드 색 하나만 쓴다. 곡이 바뀔 때마다 앱 전체 색이 바뀌지 않는다.
2. **콘텐츠가 주인공이다.** 앨범아트가 크고, 글자는 위계가 분명하고, 장식은 적다.
3. **익숙한 배치.**
   - Home 맨 위: 인사말과 2열 바로가기 그리드
   - 재생 화면: 원형 재생 버튼이 가운데 있는 클래식 배치에, 앨범아트 색 그라데이션 배경
4. **손맛.** 누를 때 반응이 있고, 햅틱이 있고, 애니메이션이 60/120fps로 부드럽다.
5. **믿음직하다.** 재생이 빨리 시작되고, 업데이트가 끊기지 않는다.

비목표:
- 광고와 수익화 (법적 이유, 2026-09-21 대화 참고)
- Spotify 로고, 초록색 같은 **Spotify 브랜드 자산 사용**. 참고하는 건 느낌과 배치뿐이다.
- 원본의 기능 제거

## 2. 현재 상태 (조사 결과)

Metrolist에는 이미 필요한 기능이 많다. 다만 **기본값이 Spotify와 다르다.**

| 항목 | Metrolist 기본값 | Spotify 느낌 | 코드 위치 |
|---|---|---|---|
| 다크 모드 | 시스템 따라감 (`DarkMode.AUTO`) | 항상 다크 | `DarkModeKey`, 6개 파일에 기본값이 중복돼 있음 |
| 앱 색상 | 동적 테마 ON (곡마다 앱 전체 색 변경), 기본 색은 배경화면 색 | 브랜드 색 고정 | `MainActivity.kt:573`, `ui/theme/Theme.kt` |
| 재생 화면 | "새 디자인": 알약 모양 "재생" 버튼 | 원형 재생 버튼, 좌우에 이전/다음 | `UseNewPlayerDesignKey` (false면 클래식 배치: 반복·이전·원형 재생·다음·좋아요) |
| 재생 화면 배경 | DEFAULT | 앨범아트 색 그라데이션 | `PlayerBackgroundStyleKey` (GRADIENT 있음) |
| 음량 평준화 | ON | ON | 이미 같음 |
| 글꼴 위계 | Material 기본 | 굵고 자간이 좁은 제목 | `MaterialTheme(typography)` 미지정 |
| Home 상단 | "홈" 제목, 스피드 다이얼 페이저 | 시간대 인사말, 2열 바로가기 | `HomeScreen.kt` (2,613줄), `HomeViewModel.speedDialItems` |

## 2.1 지역 제한 발견 (2026-09-21)

한국 IP에서 `WEB_REMIX`로 Home, 탐색, 장르, 차트 페이지를 요청하면 콘텐츠 대신 이런 메시지가 온다:

> "현재 위치한 지역에서는 YouTube Music이 Premium 회원에게만 제공됩니다."

`gl`을 US나 JP로 바꿔도 같다. IP 기준으로 막는다.

반면 검색, `next`(재생 대기열/라디오), 아티스트 페이지, 재생은 된다.

추가로 확인한 제한과 Sori의 대응:

| 기능 | 한국 무료 사용자 상태 | Sori 대응 |
|---|---|---|
| Home 피드, 탐색, 장르, 차트 | Premium 전용 메시지 | Home "Sori 추천" 선반 (추천 재생목록 검색), 검색 "모두 둘러보기" 큐레이션 |
| 재생목록 페이지 (VL…) | 첫 곡 1개만, 머리 정보 없음 | youtube.com WEB 조회로 제목, 표지, 최대 5페이지를 대체 (`SoriWebPlaylist`) |
| 노래 필터 검색 | 결과 0개 | 비어 있으면 비디오 필터로 재검색 (`searchWithSongFallback`) |
| 앨범 페이지 | 정상 | 없음 |
| 아티스트 페이지 | 정상 | 없음 |
| 라디오/대기열 (`next`) | 요청당 9곡 정도 | 없음 (연속 재생은 됨) |

설계에 주는 영향:
- 한국 무료 사용자의 "발견"은 **검색 기반**으로 해야 한다.
- 검색 화면 "모두 둘러보기":
  - YouTube 데이터가 있으면 그걸 쓴다.
  - 없으면 Sori 큐레이션 타일을 쓴다 (`SoriBrowseCatalog`, 타일을 누르면 검색이 실행됨).
- Home은 로컬 기록 기반 섹션(빠른 선곡, 다시 듣기, 잊힌 즐겨찾기, 바로가기)이 중심이 된다.
- 친구 로그인 "구매 창"도 이 Premium 전용 페이지와 관련 있을 가능성이 크다. 13.7.0.2의 `LoginPagePolicy`로 처리된다.

## 3. 병합 전략 (가장 중요한 제약)

- 스트림 추출 수정 같은 원본 버그 수정을 계속 받아야 하므로, **원본 파일 수정은 최소한의 "연결 지점"으로 한정한다.**
- Sori 코드는 새 파일에 둔다: `com.metrolist.music.sori.*`, `ui/theme/Sori*.kt`
- 원본 파일에 넣는 연결 코드에는 `// Sori:` 주석을 단다.
- 기본값은 원본 파일의 `defaultValue`(6곳 이상 중복)를 고치지 않는다. 대신 **처음 실행할 때 DataStore에 Sori 기본값을 심는다** ("시딩").
  - 키가 **없을 때만** 쓰기 때문에, 사용자가 직접 바꾼 설정은 절대 덮어쓰지 않는다.
  - 버전 마커(`sori_defaults_version`)가 있어서 한 번만 실행된다.

## 4. 단계별 로드맵

단계마다 따로 릴리스할 수 있다. 각 단계는 `feat/*` 브랜치에서 만들고, 사용자가 확인한 뒤 main에 합쳐서 릴리스한다.

### 1단계: 기초 (브랜드, 색, 글꼴, 기본값) ← 이번 작업
- **Sori 다크 팔레트** `ui/theme/SoriColors.kt`
  - 바탕 `#121212`, 표면 계층 `#181818 / #1E1E1E / #282828 / #333333`
  - 본문 흰색, 보조 글자 `#B3B3B3`
  - 강조색은 Sori 코랄 `#FF6B6B` (onPrimary 거의 검정), 보조 강조는 바이올렛 `#B69CFF`
  - 선택 표시(네비게이션 알약 등)는 중립 회색 `#2A2A2A`
  - 높이(elevation)에 따른 틴트는 흰색이라, 떠 있는 표면일수록 밝은 회색이 된다 (Spotify 방식)
- **Theme.kt 연결:** 기본 색일 때
  - 다크 → Sori 팔레트
  - 라이트 → Sori 코랄을 시드로 한 materialkolor 팔레트
  - 사용자가 다른 색을 고르면 기존 동작 그대로
  - 트레이드오프: 기본 색에서 "배경화면 색 따라가기"(Android 12+)는 없어진다. 브랜드 일관성을 우선한 결정이다.
- `DefaultThemeColor`를 `#ED5564`에서 `#FF6B6B`(Sori 코랄)로 바꾼다. 테마 선택 화면의 "기본" 색 견본도 같이 바뀐다.
- **글꼴 위계** `ui/theme/SoriTypography.kt`
  - Material 기본 크기와 줄 높이는 그대로 둔다 (레이아웃이 깨지지 않게)
  - display/headline/title만 굵기 Bold~ExtraBold, 음수 자간
  - 사용자 지정 글꼴은 넣지 않는다 (APK 크기 증가 대비 효과가 작다고 판단)
- **Sori 기본값 시딩** `sori/SoriDefaults.kt` + `App.kt` 한 줄. 모두 키가 없을 때만 쓴다.
  - `DarkModeKey = ON`
  - `DynamicThemeKey = false` (앱 색 고정. 재생 화면은 따로 앨범 색 그라데이션을 씀)
  - `UseNewPlayerDesignKey = false` (클래식 원형 재생 버튼 배치)
  - `PlayerBackgroundStyleKey = GRADIENT`
- 성공 기준:
  - MuMu 캡처에서 Home, 보관함, 재생 화면이 모두 `#121212` 계열 중립 다크에 코랄 강조로 나옴
  - 재생 화면에 원형 재생 버튼과 그라데이션 배경이 나옴
  - 사용자가 직접 바꾼 설정은 유지됨 (단위 테스트로 보장)

### 2단계: Home
- 상단 제목 "홈" 대신 시간대 인사말 (좋은 아침/오후/저녁이에요)
- 첫 섹션을 **2열 바로가기 그리드**로 바꾼다. 최대 8개, 가로로 긴 타일(작은 아트 + 제목). 데이터는 기존 `speedDialItems`를 재사용한다.
  - 기존 스피드 다이얼 페이저는 Sori 기본 섹션 순서에서 이 그리드로 대체된다.
- 섹션 제목 스타일은 1단계 글꼴(titleLarge Bold)로 자동 반영된다.
- 구현: `sori/ui/home/QuickAccessGrid.kt` + `HomeScreen.kt`에 연결 한 곳

### 3단계: 재생 화면과 미니플레이어
- 앨범아트 모서리 8dp, 제목/아티스트 왼쪽 정렬, 좋아요는 오른쪽 (클래식 배치를 다듬는 수준)
- 미니플레이어: 앨범 색 틴트 배경, 아래쪽에 얇은 진행 막대 (`MiniPlayerBackgroundStyle` 활용)
- 재생 화면 아래로 스크롤하면 가사 미리보기 카드

### 4단계: 보관함
- "내 라이브러리" 헤더 (프로필 아바타 + 제목 + 검색/추가)
- 필터 칩 (재생목록, 아티스트, 앨범, 다운로드됨)
- 목록/그리드 전환, 최근 재생 순 정렬 기본값

### 5단계: 손맛과 성능
- 좋아요, 재생/일시정지, 길게 누르기에 햅틱
- 카드와 타일에 누를 때 살짝 줄어드는 효과
- Baseline Profile로 첫 실행과 스크롤 버벅임 줄이기
- 시작 시간 측정

### 6단계: 마감
- 빈 화면과 로딩 스켈레톤 통일, 아이콘 일관성 점검, 한국어 문구 다듬기 (번역투 제거)

## 5. 위험과 대응

| 위험 | 대응 |
|---|---|
| 원본 병합 충돌 | 새 파일 + `// Sori:` 연결 지점 + 기본값 시딩 |
| 기존 사용자 설정 덮어쓰기 | 키가 없을 때만 쓰고 버전 마커로 한 번만 실행. 단위 테스트로 보장 |
| 색 대비 부족 | 본문 흰색/`#B3B3B3`, 강조 코랄과 바탕 `#121212`의 대비 약 7:1 |
| 라이트 모드 사용자 | 시딩은 다크 ON이지만 설정에서 라이트로 바꿀 수 있고, 라이트에도 Sori 시드 팔레트가 적용됨 |
| 검증 | 단위 테스트 + MuMu에서 화면 캡처로 전후 비교 |

## 6. 이번 밤 작업 범위
- 1단계 전체 구현 (`feat/spotify-quality` 브랜치)
- 디버그 APK와 전후 캡처
- 2단계 이후는 이 문서의 로드맵대로 다음 작업으로 남긴다
- **main 병합과 릴리스는 사용자 확인 후에 한다**
